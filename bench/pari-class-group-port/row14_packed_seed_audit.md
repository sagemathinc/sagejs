# Row-14 packed relation seed audit

This prerequisite connects the immutable row-14 initial capsule to the normal
resident relation cache without parsing the 96.8 MB W0 beside a native root.
It imports only the authenticated 42-relation initial boundary. No
post-initial candidate, HNF, acceptance, class, regulator, or unit event is an
input.

`row14_initial_relation_seed.py` expands each sparse initial column only inside
the isolated kernel and inserts it through `pari_prepared_add_relation`. The
result is the exact fresh prefix state `[42,8110,757,7,0,806]`. Principal
generators are scalar coordinates and metadata tokens are regenerated in
source order.

Relation-state slot 3 is `target - rows = 7`; it is unrelated to the outer
collector's separately owned `Nrelid = 4` schedule slot. The focused checker
asserts both values and their non-equivalence so the two state machines cannot
silently drift together.

The dominant 799-by-8,110 relation owner uses the existing canonical
one-limb `IntegerBuffer`, not a new or reinterpreted buffer type. Its signed
size and unsigned limb arrays occupy 77,758,680 bytes. A checked store fails
if a later relation exceeds that word capacity; after such a late failure the
caller must discard private scratch and restart from the authenticated capsule.

The focused checker authenticates and regenerates the capsule, differentially
executes GMP and tagged native storage, compares every cell of all 42 dense
columns and generators, checks the one-word representation, rejects a changed
first-nonzero hint, and proves a one-slot-short owner fails before mutation.

The authentic 42-to-802 collection/HNF run remains the next gate. Connecting
the seeded prefix to that root, and sizing its copied HNF input by the live
806-column target instead of the unrelated 8,110-record cache reserve, are not
claimed by this cut. The existing fresh-cache root remains unchanged.
