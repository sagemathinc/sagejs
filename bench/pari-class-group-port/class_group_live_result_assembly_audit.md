# Live class cleanarch and Buchall assembly

This component closes the class-only final-result edge for the authentic
totally real cubic `x^3 - 20018*x + 20034`. It consumes only two live owners:

- the qualified resident computation, pinned by its content hash; and
- the immutable, separately authorized `h=1` class-correspondence result.

No checked data fixture and no external executable supplies an answer. The
ordinary Python implementation reruns the resident relation/HNF witness, Smith
transform, final logarithm transform, equal-bound honesty condition, and the
source-translated transactional `cleanarch` leaf. It then cross-checks the
fresh Smith and presentation outputs against the immutable class owner before
constructing the exact `Ur`, `M1`, `M2`, `Ga`, `Ge`, `GD`, `ga`, and `clg2`
Buchall result.

Publication is atomic. All computation, owner replay, provenance comparison,
and payload validation happen before the publisher lock. A failed input cannot
change `current()`, while concurrent identical publications converge to one
immutable content hash. Cold replay recomputes the complete payload from the
same live owners, so coordinated rehashing of a detached result is insufficient
to authorize a mutation.

For this owner the live native status is
`[0,1,1,48,48,7,7,73,8,0]`: equal bounds authorize the honesty skip, seven
class-log columns publish, 73 relations support the rank-eight presentation,
and no public-completion bit is set. The checker compares CPython composition
with generated JavaScript, GMP, and tagged execution of that same native leaf.

The result is intentionally class-only and conditional on the recorded PARI
class-correspondence assumption. It does not include the unit group, does not
claim Phase 5, and is not a public class-group or class-and-unit result. The
remaining public gaps stay embedded in the immutable terminal record.
