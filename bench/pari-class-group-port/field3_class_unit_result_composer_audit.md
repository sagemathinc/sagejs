## Injection boundary

`prepareField3ClassUnitResult` accepts the
`field3-unit-correspondence-boundary-v1` capability.  It must contain exactly
3,913 canonical transform entries and a separately supplied synchronous replay.
That replay must bind:

- the fixed retained relation and suffix authority roots;
- the transform digest;
- both exact kernel and packed-log transform identities;
- exact principal-ideal-one reconstruction;
- same-run suffix ownership; and
- the internal-only terminal tier.

Only after that replay succeeds does the adapter construct and seal the
field-neutral payload.  Even then it returns only
`ready-for-out-of-band-publication-authority`.  Publication requires a second,
separately transported `ClassUnitCorrespondenceResult` authority which replays
the complete payload.  `publishPreparedField3Result` verifies into a detached
candidate before the neutral publisher's first atomic assignment.  The sealed
bytes are stored as an immutable hexadecimal string so caller-visible mutation
cannot alter the prepared candidate.

This two-boundary design is deliberate: the transform owner does not
authorize its own class/torsion evidence, and the composer cannot authorize its
own final envelope.
