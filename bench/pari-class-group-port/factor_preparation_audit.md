# Factor-polynomial preparation checkpoints

The flag-zero factorization needed for prime descriptors is not the
degree-pattern path already used by `get_fs`. In particular, PARI 2.17.4
selects Cantor/Shoup/EDF for binary degree-three/four factor output, whereas
the degree-only path uses Berlekamp. Retaining coefficients from the latter
would give correct factors but would not preserve the experiment's algorithm.

## Binary factor output

`f2x_small_polynomial_factor.py` follows the actual flag-zero path: squarefree
layers, Shoup DDF, source randomized EDF and final factor ordering. Polynomials
use low-bit-first packed integers. Random candidates are generated by the
translated resident PARI generator, not supplied by a replay fixture. The
source degree-two special cases remain special cases; no database of answers
is used. All 28 monic binary polynomials of degrees 2–4, under three seeds,
match PARI's factor coefficients, exponents and complete final RNG states.
All 84 cases pass CPython, JavaScript, GMP and tagged execution, with all
same-source scratch, draw counts, sentinel tails and atomic-invalid guards.

`c4f0aaebf04dc427e875b44ce1f5a5f0ef66a22d46d276a9fb69ccd3182189bd`.
The task consumed 33.47 CPU seconds including failed oracle/compiler attempts
and a superseded pre-format run; final peak child RSS was 337900 KiB. A local
initialization resolves the compiler's conservative definite-assignment check
after a source `while True` loop without changing the mathematical branch.
Independent review found no binary-EDF/RNG integration blocker.

See [resident RNG evidence](pari_random_audit.md) for seed, draw, rejection,
state serialization and representation details. This establishes stream
correspondence, not PARI-equivalent allocation or word-operation costs.

## Odd-prime DDF and half-GCD

[The DDF audit](flx_small_ddf_polynomials_audit.md) records actual component
polynomials with the existing degree-only arithmetic schedule unchanged.
It does not yet complete odd-prime equal-degree factorization.

`flx_small_halfgcd.py` translates `Flx_halfres_basecase` without resultant
accumulation, for the strict descending-degree calls needed by randomized
minimal polynomials. Inputs satisfy 1<=degree(a)<=8 and degree(b)<degree(a),
and the caller supplies canonical coefficients with the stated actual
degrees, over an odd prime <=3037000493. These degrees are below both pinned
GMP half-GCD thresholds (at least 31 and 120); no recursive half-GCD algorithm
is replaced. The four polynomial matrix entries retain the source quotient,
swap and subtraction schedule. Rotating workspace offsets implement the
temporary swaps; fixed nine-slot padding remains representation overhead.

528 cases across primes 3,5,37,2147483647 match all four execution modes and
the PARI transformation matrix. Six invalid degree/prime/storage/overlap
controls fail atomically. Input owners and tail sentinels are preserved.
Independent review checked degree/threshold selection and both disjoint slot
rotations. Arbitrarily malformed coefficient arrays are outside the stated
canonical-input contract, as for the existing low-level Flx helpers.

## Boundaries

The [modular resultant audit](kummer_resultant_audit.md) covers the generator
correction dependency separately. Complete odd-prime factorization, Kummer
descriptor assembly, and full driver integration are still separate gates.
No whole-engine timing, source-language parity, broad-degree support or
nfinit-input completion is asserted by these component checks. All sources
retain upstream GPL attribution, and native compilation lowers those actual
Python bodies.
