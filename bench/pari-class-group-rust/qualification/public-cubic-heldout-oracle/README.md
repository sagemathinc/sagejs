# Restricted held-out cubic oracle comparison

This process starts only after the answer-free held-out executor has terminated.
It opens the private Rust result bundle and the hash-bound private qualification
evidence, but it never imports a process-launching module and cannot invoke the
Rust executable.

The verifier checks all exact evidence available from the independent oracle:
polynomial identity, signature, equation-order index, field discriminant,
candidate and completed class number and invariant factors, and unit rank. Its
receipt contains only case IDs and named pass/fail checks. Neither expected nor
actual mathematical values are copied. A forbidden-key scanner runs before
the receipt is written. The separate `scan_receipt.py` publication check also
enforces exact top-level, case, and comparison-check schemas; allowed statuses;
twelve unique matching case IDs; and the one-way executor/verifier process
claims. This is a structural information-flow check, not a proof against
arbitrary covert encoding in otherwise permitted timing or hash fields.

Run only after `public-cubic-heldout-corpus/run.py` has completely finished:

```bash
python3 bench/pari-class-group-rust/qualification/public-cubic-heldout-oracle/verify.py \
  --private-results "$private_dir/rust-results.json" \
  --private-evidence /secure/qualified-panel-evidence-v1.json
```

A structural or hash-binding error produces no receipt. A mathematical failure
does produce an atomic redacted receipt and returns nonzero, so no failed case
can disappear. Review the generated receipt with `scan_receipt.py` before
publishing it.

`receipt.json` is the byte-preserved original blind comparison. After the
identity audit, `strengthened-receipt.json` is generated by re-verifying the
same already-terminated private Rust bundle; Rust is not rerun. The latter
adds equality checks for commit, source closure, binary bytes/digest, linkage
digest and no-PARI flag, panel/selection/config identities, and campaign end
and duration. It explicitly records that the original policy was uncommitted,
the campaign was not preregistered, and this is a post-hoc verifier replay
rather than a second Rust execution.
`historical-status.json` binds both byte-preserved initial receipts, the current
formatted executor and verifier sources, the strengthened verifier-only replay,
and the committed untouched confirmation manifest. The publication scanner
checks each digest and refuses any claim that the initial policy was committed
or preregistered.

Historical qualification note: this comparison belongs to the initial blind
campaign whose policy was uncommitted and therefore not preregistered. Its
3/12 result remains historical evidence. Any failure-motivated fix must also
pass the untouched v2 inputs in `public-cubic-heldout-confirmation/`.
