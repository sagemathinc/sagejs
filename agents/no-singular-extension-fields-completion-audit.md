## Representation and resource decisions

The locked Wasm GMP headers use 32-bit limbs. The generated finite-field
resource binding checks `characteristic <= UWORD_MAX` before casting to a
FLINT word. The intended common `fq_nmod_mpoly` bound is therefore
`2 <= p <= 4294967295`, with primality required. This is a representation
ceiling, **not a qualification claim**: boundary primes, arithmetic, and
adapter conversions still need the full F0/F4 evidence. Field cardinality
`p^d` is distinct from this characteristic bound. Native scalar coordinate
export also tests a 127-bit characteristic, but that does not qualify native
multivariate or Wasm support at that size.

The first coefficient codec has explicit limits: degree at most 1024, at
most 4096 decimal characters per integer coordinate, and at most 1 MiB of
coordinate text per coefficient. Integers use canonical decimal strings;
prime residues and rational pairs must already be canonical. Enumeration
checks the full field cardinality against a caller-provided limit before
creating an iterator. These limits do not replace future Gröbner work/term,
time, and output budgets.

The legacy native `fqCoordinates` export is a host adapter, not a new
mathematical algorithm: it copies a FLINT power-basis polynomial into exact
host integers. It serves existing native finite-field values; Wasm retains
its already-declared `fq_element_coordinate_bytes` resource operation.
Neither path parses printed expressions or transfers pointer identities.

The lazy polynomial-algorithms source budget increases from 260000 to 262000
bytes for the exact-field contract. No eager-loading or browser payload
ratchet is implied; production compressed-size evidence is still pending.
